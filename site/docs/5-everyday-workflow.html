5. Everyday workflow

5.1 See what changed

Open File status (sidebar). Files are grouped:

  • Conflicts – needs your decision (see section 10).
  • Staged – will be included in the next commit.
  • Unstaged – changed but not yet staged (includes new untracked files, marked U).

Click a file to see its changes on the right. Colours: green = added, red = removed. Badges: M modified, A added, D deleted, R renamed, U untracked, ! conflict.

5.2 Stage and unstage

  • Click + next to a file to stage it (or × to unstage). Double-click a row for the same effect.
  • Stage all / Unstage all buttons are in each section header.
  • Stage only part of a file: with the file open in the diff,
    • click Stage hunk to stage one block of changes, or
    • tick the checkboxes beside individual changed lines and click Stage N lines. This lets you split one messy edit into several clean commits. (In a hunk that touches the very end of a file lacking a final newline, only whole-hunk staging is offered, to avoid corrupting the file.)
  • Discard changes (↶ icon or right-click → Discard changes…) throws a file's unstaged changes away. This cannot be undone; the app asks first.

5.3 Commit

  1. Write a message in the box under the lists. Aim for a short first line (the counter turns amber past 72 characters).
  2. Press Commit or Ctrl+Enter.
  • Amend last commit – tick the box to rewrite the previous commit with the currently staged changes and/or a new message. Don't amend a commit you've already pushed and shared.
  • The history icon in the corner of the message box opens a list under the box with the latest commit messages (from this repository and from what you committed here) and your most used ones. Click one and it goes straight into the message box.
  • Commit & push… commits, then opens the Push dialog.

5.4 Push your work

Press Push. The dialog says what is about to happen (how many commits go to which branch, or that the branch has no upstream yet, or that you need to pull first) and lets you choose the remote and the branch from a list. Tick Track this remote branch the first time you push a new branch. Force push (with lease) overwrites the remote branch only if nobody else has pushed since you last fetched — use it after rewriting history (rebase/amend), never casually.
