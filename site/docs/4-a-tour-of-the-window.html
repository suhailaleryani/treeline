  • Toolbar badges: the number on Commit is how many files changed; on Push how many commits you haven't pushed; on Pull how many commits are waiting on the server.
  • Branch chip main ↑1 ↓2 – you are 1 commit ahead of and 2 commits behind the remote branch.
  • Sync subs appears when the repository has submodules (section 9). Click it to switch the submodules to the current branch; the small arrow beside it offers Sync (the same) and Sync and pull (switch, then pull each one).
  • More holds the less common actions: Merge into several branches… (merges one branch into several at once, with a conflict check first; section 10), Clean up merged branches… and Show in Explorer / Finder, plus any toolbar buttons that do not fit the window. They are ordinary toolbar buttons that start here: click Show in toolbar next to one to bring it out (see Ordering the toolbar below). Add makes a button of your own.
  • Hover for hints. The buttons in the conflict resolver (Use ours, Keep theirs, Mark resolved …) explain exactly what they do and name the branches involved.
  • Right-click almost anything (branches, tags, stashes, files, commits, submodules) for its actions.
  • Drag the thin dividers between panels to resize them, including the edge between the sidebar and the main area (160 to 600 pixels); sizes are remembered. Double-click a divider to go back to its usual size.
  • Theme: the ☀ button switches light/dark (or choose “follow system” in the command palette).
  • Command palette (Ctrl+K): type to find any action — Fetch, New branch, Check out x, Open bookmark y, Run a custom button…
  • This guide is built into the app. Press F1 or click the ? button at the top right. It opens in its own window and works offline. Error panels have a Learn more button that opens the page on fixing errors, and the command palette has shortcuts to the most useful pages.

The built-in terminal

The Terminal toolbar button shows and hides a terminal inside the window (or press Ctrl+``, Cmd+`` on a Mac). It starts a shell in the folder of the repository you have open: PowerShell on Windows, your login shell on macOS and Linux. It is there for quick commands such as git reflog, without leaving Treeline.

  • It stays put. The terminal is not part of History or File status: it keeps its place and its contents when you switch views or tabs. Hiding it does not end anything; a command that is running keeps running, and the text is still there when you show it again. Terminals end when you close them or quit the app, and are not restored at the next start.
  • Tabs. Click + in a terminal's header to open another shell in a new tab, and the ✕ on a tab to end that shell. A tab is named with its number and the folder it started in; hover it for the full path.
  • Divide. Divide adds a new piece next to this one (below it, when the pieces are on the right), each with its own tabs, so you can watch a build in one and work in another. Click a piece to give it the keyboard; the one you are typing in has a blue outline when there is more than one.
  • Move a piece to the right (or back to the bottom). Move right / Move bottom sends just that piece to the other side of the window; the others stay where they are. Pieces at the bottom sit side by side; pieces on the right stack from top to bottom. A moved piece keeps its shells running and its text.
  • Resize. Drag the edge of the terminal area (double-click it for the usual size). The bottom and the right each remember their own size, and pieces on the same side share the room equally.
  • Restart here replaces the current tab's shell with a new one in the repository you have open now. A terminal starts in the repository that was open when you made it and does not follow you when you switch tabs; use cd, or Restart here. When a shell ends (you typed exit) the tab says so and waits.
  • A real window instead. The small arrow next to the Terminal button (and Open an external terminal window here in the command palette) opens your system's terminal in the repository folder, as older versions of the button did.
  • Ctrl+`` and Ctrl+Tab` are handled by Treeline and are not sent to the shell.

The shell runs with your own rights, exactly as a terminal you opened yourself, and only in a folder you have opened in Treeline.

Custom buttons

Click Add in the toolbar (or More → Add custom button…) to make a button of your own. The dialog shows a live preview of the button as you type and offers four kinds:

Kind What it does
Shell command Runs a command in the repository's folder (for example npm test) and shows its output when it ends. It is stopped after 10 minutes.
Git command Runs git with the arguments you type (for example fetch --prune); no shell is involved.
Command in a terminal window Opens a terminal in the repository's folder and runs the command there, so you can watch it and type into it.
Open a link Opens an http://, https:// or mailto: link, for example your CI page.

In a command you can write {branch} (the current branch), {repo} (the repository folder) and {remote} (the first remote's address, without any password). The three buttons under the command field insert them where the cursor is. Treeline refuses to run a shell command whose branch or folder name holds a character that could be misread by the shell, and tells you why.

Custom buttons run programs on your computer, so only create commands you understand. A button never runs by itself: it runs when you press it, and by default only after showing you the exact command.

Save it for decides where the button lives: Every repository (the whole app), This repository (in every tab that shows it) or This tab only. Buttons are kept in Treeline's own settings on your computer. They are never read from, or written into, a repository, so cloning someone else's repository can never add a button that runs a command.

Pick an Icon from the grid (or leave it on Auto to use the icon of the kind of button); the preview shows it.

Tick Show it in the toolbar to put the button in the toolbar; otherwise it is listed in the More menu. Ask before running it shows the exact command and waits for your Run (on by default).

Ordering the toolbar

More → Customize toolbar… lists every toolbar button, the built-in ones (Commit, Fetch, Pull, Push, Branch, Merge, Stash, Tag, Merge to many, Clean up, Terminal, Explorer / Finder, and Sync subs when the repository has submodules) together with your custom ones, in the order the toolbar shows them. Merge to many, Clean up and Explorer / Finder start in the More menu; every other built-in button, Terminal included, starts in the toolbar. Any of them can be moved either way. (If you saved your toolbar before the built-in terminal existed, Terminal is still in More: click Show in toolbar next to it.)

  • Drag a button in the toolbar itself. Press and hold it for a moment (the button shrinks slightly), then drag: a blue line shows where it will land. Drop it on More to put it in the menu instead. Press Esc to cancel. A quick click still runs the button, and moving the pointer before the hold is over never starts a drag.
  • Right-click a toolbar button for Move left, Move right, Move to the More menu, Add a separator after and Customize toolbar…; a custom button also has Edit… and Remove….
  • In Customize toolbar drag the grip at the start of a row, or use the arrows. The order is the same in every tab and is remembered.
  • Untick Toolbar to move any button, built-in or custom, into the More menu; tick it to bring it back.
  • A button that does not fit in a narrow window moves into More by itself, last buttons first, and keeps its order there.
  • To bring a button out of More, open the menu and click Show in toolbar at the end of its row (or tick Toolbar in this dialog). If the toolbar is already full, the button takes the place of the last one, which moves into More.
  • Separators divide the toolbar into groups. The toolbar starts with one after Commit, one after Push, and one between the two pairs of rarer actions in More. Click the separator button on a row to add a new separator after that button, move it with the arrows like any other item, or remove it with the trash icon. Separators take no room, and one that would end up at the edge of a group, or next to another separator, is not drawn. The More menu shows them too, so its buttons stay in the same groups.
  • Edit and the trash icon change or remove a custom button (built-in buttons cannot be edited or removed).
  • Reset order puts the buttons and separators back in their usual order, all in the toolbar. Custom buttons are kept.

Each custom button also appears in the command palette as Run: name.

While it runs and afterwards. A button whose command is running pulses. A shell or git command that fails, or that prints something, shows its full output in a panel with the command, a Finished or Failed mark and a Copy output button. One that succeeds without printing anything only says so in a short message. Terminal-window and link buttons open their window or page and show no panel.

If a button does not run. Treeline says why in a message: a name that is empty or too long, a link that does not start with http://, https:// or mailto:, a {branch} used while no branch is checked out, a branch or folder name with a character that is unsafe inside a shell command (such as ", %, $ or a backtick), or the settings file buttons.json being unreadable. A shell command that exits with an error shows its output in the message. On macOS and Linux the terminal-window kind needs a terminal program (Terminal on macOS; x-terminal-emulator on Linux).
